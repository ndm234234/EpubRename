# Folders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each person can make named folders (collections) in the catalog, put a book into any number of them and take it out again, open one folder at a time; folders follow the account to all devices.

**Architecture:** Folders are a new part `shelves` of the account's sync document, kept locally in `localStorage["epubLibrary:shelves"]`; the servers don't change. Books are named by the reader's book id, which `make_server.py` adds to the catalog's data. Merging goes in `reader/sync-merge.js`, the folder edits in a new pure module `reader/shelves.js`, the UI in the catalog page inside `make_server.py`.

**Tech Stack:** Python 3 (make_server.py, unittest/pytest), plain browser JS (ES5 style in `reader/sync*.js`, modern JS in the catalog page), `node --test`, headless Chrome checks via `tests/reader/cdp.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-27-folders-design.md`

## Global Constraints

- Nothing on disk changes: no moving, copying or editing book files; the sync servers (`launchers/library_sync.py`, `launchers/library-sync.ps1`) are not touched.
- Book id = text of the first `dc:identifier` element in `<metadata>`, untrimmed, else `dc:title` text, untrimmed, else the file name — exactly as `reader.html` `openBook` (`md.identifier || md.title || fileName`) with epub.js's `getElementText` (first element, `childNodes[0].nodeValue`).
- The local key is `epubLibrary:shelves`; the document part is `shelves`; `v` stays 1.
- Doc shape: `shelves[<folder id>] = {name, named, created, books: {<book id>: {time} | {time, out: true}}}` or `{deleted: time}`.
- A deleted folder stays deleted in every merge. Per (folder, book) the later `time` wins. Name: the later `named` wins.
- UI copy is English; the UI word is "Folders". Names: trimmed, 1–60 characters, unique among the person's live folders ignoring case (the catalog's collator, `sensitivity: "base"`).
- The folder strip is hidden while there are no live folders.
- No per-account local storage; one set of folders per device (spec non-goal).
- Test data uses made-up names only (Jane Doe, John Roe, "A Quiet Harbour", "Second Tide"); no real book names in tests or docs.

## Review Focus

- A book whose file is renamed after it was put in a folder stays in the folder → Task 1 (id from metadata, not path) and Task 6 check 5.
- A folder names a book that is not in this library → not shown, not counted, entry kept → Task 4 test `list counts only books in the library`, Task 6 check 4.
- Taking a book out on one device while another device, offline, still has it in → the later action wins after both sync, the out never comes back older → Task 2 tests, Task 7 check.
- The folder open in the catalog is deleted on another device → the catalog shows All books after the sync, no error → Task 5 step (onRemoteChange), Task 7 check.
- Back button order on a phone: folder → book page → Back → folder → Back → All books; a reload in a folder keeps it → Task 6 check 3.

### Task 4: `reader/shelves.js`, the folder edits

**Files:**
- Create: `reader/shelves.js` (installed next to the catalog by `install_reader`, which copies all of `reader/`; loaded by the catalog in Task 5)
- Test: `tests/sync/shelves.test.mjs` (loaded with `vm` like the other two)

**Interfaces:** pure functions on the shelves map; they never mutate their input and return a new map. `globalThis.LibraryShelves`:
- `list(map, haveBook: (id) => boolean, compare: (a, b) => number)` → `[{id, name, books: string[]}]`, live folders only, sorted by `compare` on names; `books` only ids with `haveBook(id)` true and not `out`.
- `has(map, folderId, bookId)` → boolean (live folder, entry not `out`).
- `checkName(map, name, compare, exceptId?)` → `{name}` trimmed, or `{error: "empty" | "long" | "taken"}` (`long` above 60 characters; `taken` when `compare(x.name, name) === 0` for another live folder).
- `create(map, name, now, compare)` → `{map, id}` or `{error}`; id = `now.toString(36) + "-" + random 6 base-36 chars`; sets `name`, `named: now`, `created: now`, `books: {}`.
- `rename(map, id, name, now, compare)` → `{map}` or `{error}`; sets `name`, `named: now`.
- `remove(map, id, now)` → map with `id: {deleted: now}`.
- `setBook(map, id, bookId, inside: boolean, now)` → map with `books[bookId] = inside ? {time: now} : {time: now, out: true}`; on a deleted or unknown folder returns `map` unchanged.
