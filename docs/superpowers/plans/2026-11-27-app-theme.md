# One Theme for the Whole App — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The catalog and the reader share one theme — Auto · light · sepia · dark — chosen from a button in either, stored in the reader's synced prefs.

**Architecture:** A small shared script `reader/theme.js` (copied next to the catalog with the rest of
`reader/` by `install_reader`, and listed in the offline shell by `write_library_list` automatically)
reads and writes `epubReader:prefs.theme`, resolves Auto through `prefers-color-scheme`, paints
`<html data-theme>` and the `theme-color` meta before the first paint, and reports system and
other-tab changes. The reader and the catalog each call it; the reader also selects the resolved
theme inside epub.js.

**Tech Stack:** plain browser JS (no build), Python `make_server.py` page template, epub.js, Node
`node:test` + `vm` for unit tests, headless Chrome via `tests/reader/cdp.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-27-app-theme-design.md`

## Global Constraints

- Theme values: `"auto" | "light" | "sepia" | "dark"`, cycled in that order; anything else stored reads as `"auto"`.
- Stored in `localStorage["epubReader:prefs"].theme` (other fields kept as they are); a change sets `epubReader:prefsTime` to `Date.now()` and calls `Sync.changed()`. No change to `sync.js`, `sync-merge.js` or the servers.
- Reader default `PREFS.theme` becomes `"auto"`; an existing stored theme is kept.
- Auto = `"dark"` when `matchMedia("(prefers-color-scheme: dark)").matches`, else `"light"`; it follows a system change live, also inside an open book.
- `<html data-theme>` always holds the shown theme (`light`/`sepia`/`dark`, never `auto`), set by a blocking script at the end of `<head>` — no white flash.
- The `theme-color` meta (`id="themeColor"`, one per page) gets the shown theme's `--bg`.
- Catalog sepia palette: `--bg #f4ecd8; --surface #f9f3e3; --surface-2 #ebe1c8; --text #3b2f1e; --muted #6f604a; --line rgba(59,47,30,.13); --accent #a0522d; --accent-soft rgba(160,82,45,.12); --ring rgba(160,82,45,.35); --header rgba(244,236,216,.78); --danger #b3261e`; shadows as light. Catalog light and dark palettes keep their current values.
- Button title and accessible name: `Theme: Auto (as the system)`, `Theme: light`, `Theme: sepia`, `Theme: dark`. The UI stays English; icon `i-theme` (the reader's half-filled circle).
- Printing from the reader stays black on white.
- Test and doc names are made up (no real book or author names).

## Review Focus

1. A page opened at night with Auto and a dark system: no light frame first — `data-theme` is `dark` before `DOMContentLoaded` (Task 2, Task 3 tests).
2. The system switching to dark while a book is open on Auto: the book's text and background change too, not only the bars (Task 2 test).
3. An older or broken stored value (`"auto"` seen by nothing, `"blue"`, prefs missing, prefs not JSON): shown as Auto, no exception (Task 1 tests).
4. Catalog and reader open in two tabs: pressing the button in one repaints the other (Task 3 test via the `storage` event).
5. The catalog's top bar on a 390px phone still fits with the new button: no sideways scroll (Task 3 test).

### Task 1: `reader/theme.js`, the shared theme helper

**Files:**
- Create: `reader/theme.js`
- Test: `tests/sync/theme.test.mjs` (runs with `node --test 'tests/sync/*.test.mjs'`)

**Interfaces:**
- Produces `window.AppTheme`:
  - `THEMES: ["auto","light","sepia","dark"]`
  - `stored(): string` — `epubReader:prefs.theme` if in `THEMES`, else `"auto"` (missing key, bad JSON, storage throwing → `"auto"`)
  - `shown(t = stored()): "light"|"sepia"|"dark"`
  - `next(t): string` — the following value in `THEMES`, wrapping; an unknown `t` → `"light"` (the one after auto)
  - `label(t): string` — the titles from Global Constraints
  - `paint(t = stored()): void` — `document.documentElement.dataset.theme = shown(t)`; `#themeColor`'s `content` = `getComputedStyle(documentElement).getPropertyValue("--bg").trim()` when non-empty
  - `save(t): void` — merges `{theme: t}` into the stored prefs object (a non-object → `{theme: t}`), sets `epubReader:prefsTime`, then `paint(t)`. Does not call Sync (the caller does).
  - `watch(fn): void` — `fn()` on a `prefers-color-scheme` change and on a `storage` event whose `key` is `epubReader:prefs`
- On load the script calls `paint()` once.
